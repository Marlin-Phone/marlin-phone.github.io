## 背景：8G 不够用，准备升级 16G

我有一台 2014 年的老平台小主机（HP EliteDesk 800 G1 DM，Q87 芯片组，i3-4330T）当家庭服务器，跑 Docker 全家桶后 8G 内存被吃到只剩 500MB，靠 swap 硬扛。于是决定升级：淘了两条二手三星 8G DDR3L 笔记本内存（204 针 SO-DIMM，低压 1.35V，标签显示 2Rx8 双面 16 颗粒），共 130 元。

按"容量相同自动双通道"的常识，拆下原来的 4G×2，换上 8G×2——结果**开机直接挂**。一段本以为 5 分钟的升级，变成了两天排障。这篇文章记录完整过程，希望能帮到同样在老平台上升级内存的人。

## 症状：单条能开，双条必挂

最诡异的症状：**任何一条 8G 单独插任意槽位都能正常开机，但两条一起插就点不亮**（听到一声蜂鸣，无画面）。原装的 4G×2 双通道一直稳定。

这个"单条全好、双条全挂"的组合，把常见原因逐个排除了：

| 排查项 | 结果 |
|---|---|
| 内存条物理损坏 | ❌ 排除（两条单测都能点亮） |
| 插槽/通道故障 | ❌ 排除（原装 4G×2 双通道正常） |
| 电压/类型错误 | ❌ 排除（标签确认 PC3L-12800S 低压，规格完全正确） |
| 清 CMOS | ❌ 无效（长按复位按钮也救不了） |
| BIOS 版本旧 | ❌ 无效（已是最新版，且官方支持 2×8GB） |
| 混插 8G+4G | ❌ 也挂（说明不是单纯容量组合问题） |

排到这里很容易下结论："这平台吃不下双面条，退货换条"——**但结论下早了**。

## 认知纠偏：关键在 SPD 年代，不是 rank 数

一开始我怀疑是 rank 数问题：两条 2Rx8 双面 = 总 4 rank，会不会是平台双通道上限？网上搜了半天，越搜越心虚：

- HP 官方明确写 "supports 2 x 8 GB"——官方推荐的内存型号本身就是 2Rx8，也就是说 2×2Rx8=4 rank 是被支持的配置；
- 社区数据里，这台机器有用户用 2×8GB 跑得好好的；
- 那我和成功案例的差异在哪？——**内存的生产年代**。成功案例用的是 2013-2016 年的老批次（SPD 老格式），我买的是 2024 年生产的新批次（标签批次号 2430 = 2024 年第 30 周）。

**关键机制**：每条内存都带一块 SPD 芯片记录时序参数（相当于"身份证"）。2019 年的老 BIOS 认识 2013-2016 时代的内存身份证格式；2024 年新制程颗粒的 SPD 带了老 BIOS 不认识的参数/字段。**单条时内存控制器睁一只眼闭一只眼凑合能用；双条时要做双通道协调训练，一较真就失败**——POST 停在内存初始化阶段，只发一声蜂鸣。

> **结论：老平台升级内存，判断兼容性看"生产批次/SPD 年代"比看"单面双面/rank 数"更靠谱。** 同代的条（哪怕 2Rx8）大概率能点亮，新批次的高密度条反而可能踩坑。

## 插曲：连 BIOS 都进不去（DP 黑屏之谜）

排障需要进 BIOS 改设置，结果发现**按 ESC/F9/F10 全部黑屏**——但机器其实已经进了菜单（硬盘灯不亮 = 停在菜单等待），只是画面没渲染出来。正常启动进系统却有显示。

查了半天终于对上号：**这台机器装系统时还是 CSM/Legacy 模式，装完 Ubuntu（UEFI 安装）后变成了纯 UEFI 模式。UEFI 模式下的 BIOS 画面走 GOP 图形输出，和老平台 + 显示器 DP 口的握手有兼容问题 → 黑屏**。当年的"进 BIOS 能看到菜单"是因为还在 CSM 模式。

解法：换显示通路。VGA 模拟信号不参与数字握手，接电视 VGA 口成功看到 BIOS 画面。（备选：主动式 DP-HDMI 转接头 + 电视 HDMI 口；被动式转接头大概率无效。）

## 最终解法：POST Mode = Clear Memory，零成本救活

进 BIOS 后发现了一个之前忽略的宝藏选项（HP 老平台的 **Advanced → Power-On Options → POST Mode**）：

- **QuickBoot**（默认）：不清内存、跳过完整训练——**这正是元凶**：某次双条训练失败后，失败的训练参数被缓存，之后每次开机都复用坏参数，所以一直失败；
- **Clear Memory**：清除已保存的训练数据，下次启动强制完整重训；
- **FullBoot**：每次开机都完整训练。

选 **Clear Memory** 保存重启，再插上两条 8G——屏幕出现 `16384 MB`（16GB 被识别！）和一个"164-Memory Size Error"提示（这其实是 HP 的容量变更提示，按 F1 记录新配置即可，不是故障）。

**就这样，两条差点被退货的内存条，一分钱没花救活了。** 16GB 到手，swap 压力彻底缓解。

## 压测的坑：memtester 参数别贪大

验证稳定性时又踩了一个坑：`memtester 14000M` 压测直接把系统卡死（SSH 都连不上）。原因是**压测量超过了可用内存**（服务占用 ~7G，可用只剩 ~8G），14G 的分配触发疯狂 swap 换页，系统 thrashing 假死。

正确做法：压测量 ≈ 总内存 - 已用 - 安全余量（16G 机器建议 ≤4-8G），并且用 `systemd-run` 后台跑，避免阻塞 SSH。

## 总结：老平台内存升级避坑清单

1. **先试 POST Mode = Clear Memory / FullBoot 强制重训**——QuickBoot 缓存的坏训练参数是"单条能开、双条挂"的常见元凶，零成本；
2. **看 SPD 年代不看 rank 数**——官方支持 2×8GB 2Rx8（4 rank）；2024 新批次条在老 BIOS 上容易踩坑，2013-2016 同代条最稳；
3. **下单前让卖家发标签照片**——批次号后 4 位 = 年份+周数（如 2430 = 2024 年第 30 周），老平台认 14XX/15XX/16XX；
4. **"164-Memory Size Error"不是错误**——HP 的容量变更提示，按 F1 记录即可；
5. **BIOS 黑屏先查启动模式**——CSM/Legacy → UEFI 切换会让 BIOS 画面在 DP 口黑屏，换 VGA/HDMI 通路或改回 CSM；
6. **memtester 压测别贪大**——超过可用内存会 thrashing 卡死，压测量留足余量。
